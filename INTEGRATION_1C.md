# Интеграция с 1С (AutoTerra)

Данный документ описывает архитектуру и процесс подключения системы 1С к платформе AutoTerra.

## Архитектура интеграции

Интеграция реализована через сервисный слой `IntegrationService` с использованием паттерна "Стратегия". Это позволяет поддерживать различные протоколы обмена данными (REST, OData, SOAP) без изменения основной бизнес-логики.

### Основные компоненты

1.  **Модели данных**: В основные модели (`Product`, `ClientProfile`, `Order`, `Distributor`) добавлено поле `external_id`, которое служит уникальным идентификатором объекта в 1С.
2.  **IntegrationService**: Находится в `api/services/integration.py`. Содержит логику синхронизации:
    *   `sync_products()`: Загрузка каталога товаров.
    *   `sync_stock()`: Обновление остатков и цен.
    *   `sync_clients()`: Синхронизация профилей клиентов.
    *   `sync_orders()`: Передача новых заказов в 1С.
3.  **Стратегии интеграции**:
    *   `RestIntegrationStrategy`: Для работы через HTTP REST API.
    *   `ODataIntegrationStrategy`: Для использования стандартного интерфейса OData 1С.
    *   `SoapIntegrationStrategy`: Для работы через SOAP Web-сервисы.

## Процесс подключения новой интеграции 1С

Для реализации конкретного коннектора необходимо:

1.  Создать новый класс, наследующийся от `IntegrationStrategy` в `api/services/integration.py`.
2.  Реализовать методы `fetch_products`, `fetch_stock`, `fetch_clients` и `push_order`.
3.  Настроить расписание (Celery tasks) для регулярного вызова методов `IntegrationService`.

### Пример инициализации сервиса:

```python
from api.services.integration import IntegrationService, RestIntegrationStrategy

# Инициализация с конкретной стратегией
strategy = RestIntegrationStrategy(base_url="https://1c.example.com/api", auth=("user", "pass"))
service = IntegrationService(strategy)

# Вызов синхронизации для конкретного дистрибьютора
service.sync_products(distributor_obj)
```

## Правила сопоставления (Mapping)

*   **Товары**: Сопоставление идет по `external_id` (UID из 1С). Если `external_id` пуст, допускается сопоставление по `sku` в рамках одного дистрибьютора.
*   **Клиенты**: Основной ключ — `external_id`. Дополнительный — `inn` + `region`.
*   **Заказы**: После успешной передачи заказа в 1С, поле `external_id` в модели `Order` заполняется номером документа из 1С.

## Рекомендации по безопасности

*   Используйте HTTPS для всех соединений.
*   Храните учетные данные для доступа к 1С в переменных окружения (`.env`).
*   Логируйте все входящие и исходящие запросы интеграции для упрощения отладки.

## Excel Импорт

Архитектура 1С полностью совместима с текущим Excel импортом. Поле `external_id` остается опциональным и не мешает ручной загрузке файлов дистрибьюторами в админ-панели.
