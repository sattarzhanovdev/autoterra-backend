# Персональные цены клиентов

Приоритет: активная ClientPriceOverride → ClientBrandDiscount → personal_discount_percent клиента →
RankDiscount для ранга PartnerTier →
базовая Product.price. Персональная цена не суммируется со скидкой и может быть
выше базовой. Допустима положительная сумма до 9 999 999 999,99 ₽ с точностью до
копейки. Одна запись на пару клиент/товар; товар — от дистрибьютора клиента.
Отключение или удаление персональной цены возвращает расчёт по брендовой,
затем общей скидке, а без них — по рангу. OrderItem.price
фиксируется при создании заказа: изменение персональной цены не переписывает
существующие заказы. Новые позиции корректировки получают актуальную цену.

В приложении: карточка клиента менеджера → «Персональные цены»; у администратора
одноимённая вкладка. Чтобы задать цену новому товару, отключите «Только
персональные цены» и найдите товар по названию/артикулу. Дистрибьютор открывает
раздел из раскрытой карточки клиента и видит цены без возможности изменения.
В Django admin у центрального администратора также есть раздел и inline клиента.

## API

Авторизация: Bearer token.

- `GET /api/clients/{clientId}/prices/` — назначенные цены (включая отключённые).
  `overridesOnly=false` включает каталог; `search` ищет по названию и артикулу;
  `page`, `pageSize` задают пагинацию. Ответ содержит `results`, `pagination`,
  `count`, `canEdit`. Строка содержит `productId`, `sku`, `name`, `productActive`,
  `basePrice`, `rankPrice`, `price` (итог), `priceSource` (`personal/personal_discount/rank/base`),
  `personalPrice`, `overrideId`, `isActive`, `updatedAt`. Денежные поля — строки
  с десятичной точкой; персональная цена и overrideId могут быть null.
- `PUT` / `PATCH /api/clients/{clientId}/prices/{productId}/` — создать/изменить:
  `{"price":"650.25","isActive":true}`. PATCH поддерживает изменение только
  активности существующей записи. Возвращается `item`, код 201/200.
- `DELETE /api/clients/{clientId}/prices/{productId}/` — удалить; повтор безопасен.
  Возвращается `item` с пересчитанной итоговой ценой и `status: ok`.

Менеджер читает/изменяет клиентов своих регионов, admin — всех клиентов.
Дистрибьютор читает только своих, запись запрещена. Клиент, курьер и эксперт
к этим эндпоинтам доступа не имеют. Клиентский каталог сам определяет клиента
по токену, а не по входному clientId. Мутации пишутся в AuditLog.

В `/api/products/` итог остаётся в `price`, добавлены `personalPrice` и
`priceSource`; `basePrice` сохраняется. Корзина использует `price`, при создании
заказа сервер рассчитывает цену заново и игнорирует присланную клиентом сумму.
`/api/distributor/stock/?clientId=...` возвращает те же ценовые данные в пределах
доступа к клиенту. Без clientId общий склад продолжает показывать базовые цены.

## Установка

1. Обновить серверный код, включая миграции 0051_client_price_override и 0052_client_personal_discount.
2. Выполнить `.venv/bin/python manage.py migrate`, затем
   `.venv/bin/python manage.py check` и перезапустить backend.
3. Собрать и установить обновлённое Flutter-приложение. Ранее собранный APK
   не содержит нового раздела управления. Старые клиенты получают итоговую
   персональную цену через существующее поле price после обновления сервера.

Тесты функции: `manage.py test api.test_client_prices api.test_rank_discounts`
и `flutter test test/personal_prices_test.dart` в соответствующих проектах.


## Персональная скидка на ассортимент

В карточке клиента distributor/admin поле «Персональная скидка, %» доступно
для изменения. Менеджер видит текущее значение своих региональных клиентов
без кнопки изменения.
Процент применяется к базовой цене каждого товара; скидки не суммируются.
Например, 1000 ₽ при 20% превращается в 800 ₽, при 15% — в 850 ₽.

- `null` — не задана, действует прежняя логика RankDiscount/PartnerTier.
- `0` — явно заданная персональная скидка 0%, скидка по рангу не применяется.
- `100` — бесплатные позиции. После подтверждения заказ с нулевой суммой
  завершается без обращения к платёжному провайдеру (Payment.provider=discount).
- Активная персональная цена конкретного товара по-прежнему важнее процента.
- Диапазон 0–100 включительно, максимум два знака после запятой.
  Округление итоговой цены — до копейки, ROUND_HALF_UP.

`GET /api/clients/{clientId}/discount/` возвращает
`{"clientId":"1","personalDiscountPercent":"20.00","canEdit":true}`.

`PATCH /api/clients/{clientId}/discount/` принимает
`{"personalDiscountPercent":"15.00"}`; для возврата к рангу передайте null.
Права общей скидки: distributor — изменение только своих клиентов,
admin — всех, manager — только чтение своих регионов. Остальные роли
не имеют доступа к этому API. Права персональных цен товаров сохранены.
AuditLog фиксирует автора, старое и новое значение, включая сброс.
Изменение через Django admin также записывается в AuditLog.
GET карточки клиента включает nullable personalDiscountPercent.
Каталог передаёт применённый процент в discountPercent, источник — personal_discount.
Открытый каталог, корзина и карточка товара обновляются через
GET /api/products/quote/?ids=1,2 каждые 5 секунд в активном приложении.
При создании или замене заказа сервер читает актуальную цену под блокировкой
клиента. Ранее созданные заказы сохраняют зафиксированную цену.

Миграция 0052 оставляет поле null у всех существующих клиентов; данные
ClientPriceOverride, RankDiscount, PartnerTier и цены заказов не изменяет.

Дополнительные тесты: `manage.py test api.test_client_discount`,
`flutter test test/client_discount_test.dart test/personal_prices_test.dart`.

## Скидки клиента по брендам

Миграция `0057_clientbranddiscount` создаёт ClientBrandDiscount с уникальной
парой client/brand и ограничением процента 0–100. Процент имеет максимум
два десятичных знака. 0% — явное правило без процентной скидки для бренда;
удаление записи возвращает общую скидку или ранг. Скидки не суммируются.

Бренды берутся из Product.brand у дистрибьютора клиента. Для совпадения и
хранения ключа используются Unicode NFKC, casefold и удаление лишних пробелов.
Написание в карточках товаров не меняется. Bosch/BOSCH/bosch — одна скидка.
Правило связано с клиентом и брендом, а не с ID товара, и переживает повторный
импорт Excel. Отсутствующая/пустая колонка бренда при импорте сохраняет бренд
существующего товара. Временно исчезнувшие бренды остаются в списке настроек,
чтобы можно было изменить или удалить их скидки.

API `/api/clients/{clientId}/brand-discounts/`:

- GET: `results`, `pagination`, `canEdit`; строки содержат `brand`, `label`,
  `percent` (null, если не задан), `available`. Поддержаны `search`,
  `discountsOnly=true`, `page` и `page_size`.
- PATCH: атомарное добавление/изменение до 200 брендов за запрос:
  `{"discounts":[{"brand":"BOSCH","percent":"7.50"}]}`.
  Повтор одного нормализованного бренда или неверная запись отклоняет весь пакет.
- DELETE: `{"brand":"BOSCH"}`; удаляет только правило клиента, повтор безопасен.

Права такие же, как у общей скидки: admin — все клиенты, distributor — свои,
manager — чтение своих регионов, остальные роли — без доступа. PATCH/DELETE
блокируют клиента тем же способом, что оформление заказа и персональные цены.
Изменения через API фиксируются в AuditLog.

Flutter: «Скидки по брендам» в карточке клиента; поиск, фильтр установленных
скидок, галочки, общий процент выбранным брендам и индивидуальное редактирование.
Менеджер видит экран без возможности изменения. Сохранение обновляет интерфейс;
открытый каталог/карточка/корзина используют существующее обновление quote.
Финальная цена рассчитывается сервером через price_for_client.
Старые снимки заказов не меняются; создание/замена заказа и новые позиции
корректировки получают текущую цену.

Тесты: `manage.py test api.test_brand_discounts`,
`flutter test test/brand_discounts_test.dart`.
