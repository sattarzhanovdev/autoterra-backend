# Безопасное редактирование заказа в Django Admin

В карточке заказа можно менять клиента, его магазин, способ доставки, курьера,
ожидаемую дату, комментарий и причину отклонения до оплаты и закрытия заказа.
При выборе другого клиента список магазинов обновляется автоматически.
Магазин должен быть активным и принадлежать выбранному клиенту; клиент —
дистрибьютору заказа. Курьер должен быть активным пользователем с ролью курьера.
При самовывозе назначенного курьера нужно убрать.

Смена клиента пересчитывает персональные цены. Создаётся `OrderAdjustment`
с исходными/новыми позициями и автором; заказ получает статус «Скорректирован»
и направляется новому клиенту на согласование. Дистрибьютора можно поменять
только в статусе «Новый», если все товары принадлежат выбранному дистрибьютору
и выбранный клиент также относится к нему. Автоматической замены товаров
по похожему SKU между разными дистрибьюторами нет.

Способ оплаты можно менять до создания любого платежа. При выборе наличных
проверяется разрешение клиента, курьерская доставка и положительная сумма.
После создания платежа нельзя менять способ оплаты, клиента и дистрибьютора.
При pending/waiting_for_capture блокируются изменения до разрешения платежа.
Оплаченные, отправленные, выполненные и закрытые заказы доступны для просмотра.
Системные поля и прямой выбор статуса остаются readonly.

## Изменение состава

Нажмите **Изменить состав**. Измените количество, отметьте удаление или выберите
новый товар в свободной строке. Количество 0 также удаляет существующую позицию.
Новый товар должен быть активным и принадлежать дистрибьютору заказа.
Цены, артикулы, названия и зарезервированные количества нельзя редактировать
вручную. Основной inline `OrderItem` остаётся полностью readonly.

API и Admin используют общий `api/services/orders.py`: транзакцию, блокировку
заказа и товаров, `reserve_product`/`release_product`. Уменьшение/удаление возвращает
только фактический резерв; товар «под заказ» не создаёт несуществующие остатки.
При нехватке товара, чужом товаре или удалении последней позиции вся операция
откатывается. Добавление уже выбранного товара увеличивает его позицию.

Каждое фактическое изменение состава создаёт `OrderAdjustment` с original/adjusted
snapshot и пользователем. История показывается в карточке и защищена от ручного
создания, изменения и удаления. Неизменившийся состав не создаёт лишнюю запись.
Заказы «Новый», «Подтверждён», «Скорректирован» и legacy «Принят» могут корректироваться,
если нет оплаты/незавершённого платежа. При корректировке `confirmed_at` сбрасывается.
Наличная доставка приостанавливается, отметки сборки сбрасываются; после согласия
клиента доставка возобновляется с актуальными клиентом, адресом и курьером.

## Статус

В карточке есть кнопки с подтверждением, в списке — admin actions:
подтверждение, отклонение, отмена, отправка и завершение. Все переходы проходят
через общий сервис и state machine; отмена/отклонение освобождают резерв один раз.
Администратор не может принять корректировку вместо клиента или вручную
выставить «Оплачен». Онлайн-оплата подтверждается платёжной системой,
наличные — назначенным курьером через существующий сценарий получения денег.
Завершить наличный заказ без подтверждённого получения денег нельзя.

Права Django на изменение заказа обязательны. Дистрибьютор видит свои заказы,
менеджер — заказы своих регионов; администратор/суперпользователь — общий список.
POST в админке защищён CSRF. Заказ блокируется на время проверки/сохранения формы,
а общий сервис повторно проверяет статус и платежи перед изменениями.

## Проверка

```bash
DB_ENGINE=sqlite3 .venv/bin/python manage.py test api.test_order_admin
DB_ENGINE=sqlite3 .venv/bin/python manage.py test api
DB_ENGINE=sqlite3 .venv/bin/python manage.py check
```

Миграции не требуются. Production автоматически не обновляется.
