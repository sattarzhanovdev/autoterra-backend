# Регистрация: подтверждение и доставка писем

Исправление от 20.10.2026. Активность Django User разрешает аутентификацию;
доступ к каталогу и заказам по-прежнему требует ClientProfile.status=active.
Статус «Новый» на карточке означает, что регистрация ещё не подтверждена.

## Что изменено

- Кнопка «Подтвердить регистрацию» доступна менеджеру своего региона,
  дистрибьютору своих клиентов и центральному администратору.
- `POST /api/manager/clients/{id}/approve/` переводит new/under_review в active,
  синхронизирует активность пользователя и сохраняет аудит. Повторный запрос
  безопасен. Заблокированные и архивные аккаунты этим действием не восстанавливаются.
- `GET /api/clients/{id}/settings/` дополнен canApprove. Права на финансовые
  настройки и общий редактор статуса не изменены.
- Экран ожидания проверяет `/api/auth/me/` раз в 15 секунд, при возврате
  в приложение и по кнопке. Подтверждённый статус открывает главный экран
  через существующий router/authService без повторного входа.
- Письмо на REGISTRATION_NOTIFICATION_EMAILS (по умолчанию
  zavtoterra@yandex.ru) записывается в очередь в транзакции регистрации,
  отправляется после коммита и остаётся в очереди при ошибке SMTP.
  Console/dummy/file backend не считается доставкой.

## Развёртывание backend

1. Обновить код и выполнить `python manage.py migrate` (миграция 0062).
2. Проверить EMAIL_HOST, EMAIL_PORT, EMAIL_HOST_USER, EMAIL_HOST_PASSWORD,
   EMAIL_USE_TLS/EMAIL_USE_SSL и DEFAULT_FROM_EMAIL в окружении сервиса.
   EMAIL_BACKEND должен отправлять через SMTP, а не печатать письма в консоль.
   `REGISTRATION_NOTIFICATION_EMAILS=zavtoterra@yandex.ru`.
3. Перезапустить backend штатным способом.
4. Настроить запуск `python manage.py retry_registration_emails` каждую минуту.
   Для systemd есть deploy/autoterra-registration-emails.service и .timer;
   перед установкой заменить путь /srv/autoterra-backend и пользователя autoterra
   на реальные значения. Для cron использовать Python из venv и каталог проекта.
5. Для потерянных уведомлений за 20 октября выполнить:
   `python manage.py retry_registration_emails --enqueue-since 2026-10-20`.
   Это явно создаёт очередь для app-регистраций с указанной даты и отправляет
   письма. Старые записи до внедрения очереди не содержат достоверной истории
   доставки: прежде чем задавать дату, проверить, что эти уведомления отсутствуют.

Обычный запуск команды не создаёт письма по историческим регистрациям и не
повторяет уже отмеченные отправленными. Lease защищает от параллельной обработки
и освобождается после сбоя процесса. Как и любой SMTP outbox, при аварии между
приёмом письма SMTP-сервером и записью sent_at возможен повтор письма.

Очередь: api.RegistrationEmailDelivery. Поля sent_at, attempts, last_error и
locked_until позволяют проверить состояние без вывода SMTP-паролей.

## Действующие клиенты

В обновлённом приложении открыть новые регистрации и нажать «Подтвердить
регистрацию» в каждой проверенной карточке. Клиент на старой версии может нажать
«Проверить статус»; новая версия обновит статус автоматически. Массовая активация
непроверенных аккаунтов не выполняется. Backend и новая APK нужны для новой кнопки.

Изменения проверены локально. Настройки SMTP и доступы конкретного рабочего
сервера этим документом не подтверждаются.
