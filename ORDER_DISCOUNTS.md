# Скидки текущего заказа

Клиентская цена сохраняет прежний приоритет: активная договорная цена → бренд →
общая персональная скидка → ранг → прайс. Проценты между этими источниками не складываются.
`price_details` / `price_for_client` остаются первым этапом расчёта.

`api/services/order_discounts.py:quote_order` — второй этап для корзины,
создания, замены и корректировки заказа, включая смену клиента через Admin.
Порог определяется суммой `клиентская цена × количество` до скидки за объём.
До 10000 ₽ ступень 0%; затем 3% + floor((subtotal − 10000) / 5000) × 0.5 п.п.
Ступени не складываются; сама ступень ограничена 40%.

Скидка за объём добавляет процентные пункты относительно прайса.
Из уже округлённой клиентской цены вычитается `прайс × ступень / 100`.
Все денежные операции используют Decimal. Округление до копеек — ROUND_HALF_UP;
минимальная допустимая цена — 60% прайса с округлением вверх до копейки,
чтобы даже округление не давало скидку выше 40%.

Договорная `ClientPriceOverride` не получает скидку за объём. По явно согласованному
требованию владельца задачи лимит 40% применяется и к ней: новые недопустимые
цены отклоняются API и моделью; старые значения безопасно ограничиваются при
чтении. Само сохранённое старое договорное значение не переписывается.
При изменении прайса тот же safety cap продолжает действовать.
Низкоуровневые bulk/update могут обходить model validation договорной цены;
итоговый pricing всё равно ограничивает её. Межтабличный CHECK для сравнения
с Product.price не добавлялся.

Для процентных полей ClientProfile, ClientBrandDiscount и RankDiscount есть
валидаторы модели/Admin, API (для доступных HTTP-настроек) и DB CHECK 0–40.
Миграция 0064 нормализует старые процентные правила в этот диапазон перед
добавлением ограничений. Обратная миграция не восстанавливает прежние проценты;
для восстановления исходных данных нужна резервная копия. Исторические OrderItem
не меняются; финансовая фиксация защищена существующим ensure_editable_order,
который также проверяется при замене заказа.

## API

`POST /api/orders/quote/` требует авторизованного активного клиента.
Вход: `{"items":[{"productId":"1","quantity":15}]}`.
Цена, итог и скидки из запроса не используются. Товары ограничены дистрибьютором
клиента. Повторные ID суммируются. Максимум 1000 строк и 1000000 единиц на товар.

Ответ содержит `items` с финальными `price` и `total` и `orderDiscount`:

- subtotalBeforeOrderDiscount, orderDiscountPercent;
- discountAmount (реальная экономия с учётом cap и договорных позиций), total;
- nextDiscountPercent, nextThreshold, amountToNextThreshold;
- progress, maxDiscountPercent, maximumReached, hasEligibleItems.

Decimal-поля нового API сериализуются строками, как в API договорных цен.
`amountToNextThreshold = nextThreshold − subtotalBeforeOrderDiscount`.
Progress ниже 10000 — subtotal / 10000; далее — доля интервала между ступенями.
Если весь подходящий ассортимент упёрся в cap, следующий порог не предлагается.
Для корзины только из договорных цен стимул докупить тоже скрывается.
Сумма договорных товаров учитывается в пороге смешанной корзины, но их цены
не получают дополнительную скидку.

`GET /api/order-config/` дополняется `orderDiscount` с централизованным конфигом.
`POST /api/orders/create/` дополняется вычисленным `orderDiscount`; существующий
объект `order` сохранён. Заказ каждый раз пересчитывается сервером под блокировками,
независимо от предыдущего quote. Между quote и сохранением прайс может измениться;
окончательны цены сохранённого заказа, как и раньше.

Каталог, product quote и управление ценами дополняются `effectiveDiscountPercent`:
фактическая скидка от прайса после округления. `discountPercent` сохраняет свою
семантику (0 при договорной цене). Публичный каталог по-прежнему возвращает прайс,
а явный неверный токен не превращается в анонимный доступ.

## Примеры без исходной скидки

| До скидки | Ступень | Экономия | Итого | Следующая | Докупить |
|---:|---:|---:|---:|---:|---:|
| 7000 | 0% | 0 | 7000 | 3% / 10000 | 3000 |
| 10000 | 3% | 300 | 9700 | 3.5% / 15000 | 5000 |
| 15000 | 3.5% | 525 | 14475 | 4% / 20000 | 5000 |

Прайс 1000, персональная 22%: каталог 780, effectiveDiscountPercent 22.
15 единиц: subtotal 11700, ступень 3%, финальная единица 750, итог 11250.
Прайс 1000, персональная 39%, 20 единиц: subtotal 12200, ступень 3%,
фактическая итоговая скидка 40%, единица 600, итог 12000.
