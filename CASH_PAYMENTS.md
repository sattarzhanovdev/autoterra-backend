# Наличные при курьерской доставке

По умолчанию доступ выключен для всех клиентов, в том числе существующих.
В карточке клиента администратор или его дистрибьютор включает переключатель
«Оплата наличными курьеру». Менеджер, клиент и водитель менять разрешение не могут.
Разрешение можно настроить сразу после регистрации, до активации аккаунта.

Клиент с разрешением выбирает наличные при оформлении заказа. Пока оператор
не подтвердил состав, сборка не создаётся. После подтверждения (либо принятия
клиентом корректировки) появляется задача доставки/сборки без онлайн-оплаты.
Для уже подтверждённого заказа клиент или дистрибьютор также может выбрать
наличные отдельной кнопкой. Она недоступна при начатом онлайн-платеже.
Самовывоз продолжает использовать прежнюю онлайн-оплату.

Курьер собирает позиции, отправляется в путь и видит полную сумму к получению.
Кнопка «Взял наличные» требует подтверждения фактического получения всей суммы.
Только назначенный водитель может выполнить это действие, только во время
доставки. Сервер фиксирует Payment(provider=cash), paid_at, cash_collected_by
и AuditLog. Повторные и одновременные запросы не создают второй платёж.
Сумма берётся из сохранённых сервером позиций заказа, не из тела запроса.
Доставка остаётся в статусе shipped после получения денег и затем завершается
обычной кнопкой; без подтверждения денег её завершение запрещено и курьеру,
и оператору. До получения денег наличный заказ не увеличивает оплаченный оборот.

Отключение разрешения запрещает новые наличные заказы и новые переключения,
но сохраняет способ оплаты уже оформленных наличных заказов.
Подтверждённые наличные заказы не отменяются таймером неоплаченного резерва.
Отмена заказа до отправки отменяет связанную задачу сборки.

## API

- GET/PATCH `/api/clients/{id}/cash-permission/`
  Тело PATCH: `{"cashPaymentAllowed":true}` (строго boolean).
  Доступ: admin или дистрибьютор этого клиента.
- POST `/api/orders/create/`: дополнительное поле `paymentMethod: "cash"`.
  Прежний запрос без этого поля означает `online`.
- POST `/api/orders/{id}/cash/`: выбор наличных для подтверждённого заказа.
  Доступ: клиент-владелец, его дистрибьютор, admin. Разрешение клиента обязательно.
- POST `/api/courier/tasks/{id}/collect-cash/`: получение денег назначенным водителем.

Карточка клиента включает cashPaymentAllowed; заказ — paymentMethod,
cashCollected, cashCollectedBy, canChooseCash. Задача курьера включает
paymentMethod, cashAmount, cashCollected. Существующий isPayable относится
только к онлайн-оплате.

## Обновление

1. Обновить backend из ветки adilhan_new.
2. Выполнить `python manage.py migrate` (0053_cash_payment_permissions),
   `python manage.py check`, затем перезапустить backend.
3. Установить новое приложение. Включить наличную оплату выбранным клиентам.

Миграция оставляет старые заказы в режиме online и не меняет их цены/платежи.
Тесты: `api.test_cash_payments` и Flutter `test/cash_payments_test.dart`.
