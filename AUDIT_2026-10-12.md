# Аудит AutoTerra — 12 октября 2026

Изменения внесены локально в Django и Flutter. Рабочий сервер и рабочая БД не изменялись.

## Что исправлено

- API общей скидки разрешал изменение менеджеру, а дистрибьютору давал только чтение. Теперь дистрибьютор меняет скидку своих клиентов, администратор — всех. Менеджер может читать данные своих регионов, но не менять общую скидку. Остальные роли не имеют доступа к этому API. Поддерживаются 0–100%, два десятичных знака и null для возврата к рангу. Использованы существующее поле и единый price_for_client; приоритет и права изменения персональных цен товаров сохранены.
- Добавлена форма статуса и категории в карточки клиента дистрибьютора и администратора. Значения и подписи приходят из Django STATUS_CHOICES/CATEGORY_CHOICES. После сохранения обновляются карточка и список. Категория s открывает наценку в текущем клиентском сеансе; другая категория закрывает доступ к ней. Старый API статуса и архивирование больше не позволяют менеджеру обойти новые права.
- Архив отключает учётную запись и отзывает токены; активация разрешает вход. Правила доступа учётной записи вынесены в общий сервис для API и Django admin. Блокировка проверяется сервером для действующего токена. Повторный вход после обычной смены категории или скидки не нужен; архив намеренно завершает сеанс.
- В профиле дистрибьютора добавлены «Редактировать», форма названия/email/телефона, PATCH API и проверки. Экран обновляется из ответа сохранения, email синхронизируется с User. Телефон организации не меняет логин. Отдельного поля контактного лица у Distributor нет; контактные поля — email и телефон.
- ИНН, регионы, внешний идентификатор и связи владельца этим API не изменяются. ИНН уникален и используется в интеграции; Region связан с клиентами, менеджерами и дистрибьютором. Критичные поля доступны администратору в Django admin, что объясняется в UI. Региональные списки Django admin ограничены владельцем/регионом, изменение регионов разрешено администратору с соответствующими Django permissions.
- Каталог и корзина сохраняли старые объекты товаров; обновление заказа обновляло только справочники. Добавлен собственный дистрибьютору /products/quote/ с пакетами до 200 ID. Открытый каталог, корзина и карточка товара получают свежие цены каждые 5 секунд в активном приложении, при возврате из фона и ручном обновлении. При создании сервер блокирует запись клиента и читает свежие условия цены. Наценка применяется к конечной закупочной цене. Цена уже созданного заказа сохраняется.
- Flutter принимал paymentMethod, но терял его в repository и API client. Теперь наличный способ оплаты передаётся серверу и сохраняется при открытии редактирования заказа; его изменение учитывается формой.
- Редактирование сначала отменяло старый заказ отдельным запросом. При ошибке создания нового исходный заказ уже терялся. Теперь /orders/<id>/replace/ использует существующий расчёт и создание в одной транзакции: ошибка сохраняет старый заказ и резерв. Чужие/оплаченные заказы и заказы с незавершённым платежом заменить нельзя.
- Исправлен доступ дистрибьютора к существующей сводной карточке клиента. Оболочка администратора больше не подменяет её главной панелью. Совет из карточки можно отправить только своему клиенту дистрибьютора. Убрано дублирование маршрута финансов. Старый кабинет дистрибьютора открывает рабочую главную панель.
- Удалена mock-подстановка вымышленных ключей и журналов в интеграции администратора при ошибке API. Интеграции и аналитика показывают явную ошибку и повторную загрузку, без вымышленных данных или нулевого оборота вместо ошибки.
- Исправлены callbacks setState, возвращавшие Future, в заказе, профиле эксперта, отчётах, карточке дистрибьютора и деталях заказа менеджера. Добавлены/исправлены повторная загрузка, mounted и обработка ошибки удаления точки клиента. Форма добавления товара прокручивается; ошибочные цена/остаток не превращаются в нули. Длинные сведения клиента переносятся, архив отображается корректно. Формы проверены на 320×568 и 360×640.
- Тест миграции синонимов оставлял БД на 0055 без markup_percent из 0056, ломая следующий тест регистрации. Теперь он восстанавливает все актуальные миграции. Внутренние исключения регистрации больше не отправляются клиенту.

Проверены код экранов, обработчики, маршруты, repository/API client и серверные проверки; выполнены все существующие тесты и новые регрессионные проверки. Это аудит кода и автоматизированных сценариев, а не ручное прохождение каждого экрана на Android.

## Миграции и развёртывание

Новых миграций нет: схема не менялась. Используются существующие 0052 (персональная скидка), 0055 (синонимы) и 0056 (наценка магазина).

После push:

1. Сначала развернуть backend. В его виртуальном окружении выполнить python manage.py migrate --noinput и python manage.py check, затем перезапустить Django/Gunicorn штатной командой сервера. migrate применит существующие миграции, если сервер отстаёт.
2. Проверить связь пользователя дистрибьютора с активным Distributor и принадлежность клиентов правильным distributor/region. Проверить сохранение и запрет изменения клиента другого дистрибьютора.
3. Собрать новую Flutter-версию с действующим API_BASE_URL и развернуть штатным способом. Для новых форм нужно обновление приложения, а не только Django.
4. На Android пройти скидку 10% → 0% → по рангу, персональную цену товара, смену категории на магазин и обратно, изменение контактов, каталог → корзину → заказ, наличную оплату и замену заказа. При наличии сети уже открытый каталог обновляется в пределах 5 секунд.
5. На сервере/стенде проверить настоящую тестовую оплату YooKassa и webhook, push, email, 1C, фото и скачивание/импорт файлов. Ранее созданные заказы сохраняют свои цены; заменяемый заказ создаётся с актуальной ценой.
