# Синонимы товаров

`Product.synonyms` — список альтернативных названий одного товара. Синонимы не создают новых товаров: идентичность при импорте по-прежнему определяется парой `distributor + sku`.

В Excel добавьте колонку **Синонимы** (также принимаются `synonyms` и `Альтернативные названия`). Например:

| Артикул | Название | Синонимы |
| --- | --- | --- |
| FILM-1 | Защитная пленка | укрывной материал; пленка; защитная плёнка |

Повторный импорт заменяет список. Пустая ячейка очищает список; отсутствие колонки сохраняет существующие синонимы. При отсутствии колонок цены, остатка и фото эти значения сохраняются. Персональные цены и скидки импорт не меняет.

В Django-админке и форме товара Flutter список редактируется строкой через `;`. API возвращает `synonyms` как массив строк; создание товара и JSON-загрузка склада принимают массив или строку через `;`. Отсутствующее поле при обновлении не меняет список, `[]` или пустая строка очищает его. Неверные типы отклоняются.

Все поисковые пути используют `api.services.search.search_products`: название, артикул, бренд, категория и каждый синоним. Общая нормализация запроса и данных: Unicode `casefold`, `ё → е`, визуально похожие кириллические буквы → латинские (`авекмнорстух → abekmhopctyx`), прочие символы кроме букв и цифр → пробелы, схлопывание пробелов. Все слова запроса должны встречаться в поисковом тексте, в любом порядке и в любых полях. Для артикула и названия сохраняются также строки без пробелов: `1310` / `13 10` находят `13-10`, `p800` — `P 800`. Слитный запрос дополнительно ищется в слитном артикуле. Сортировка: точный слитный артикул, начало артикула, начало названия, остальные по категории и названию. Ранжирование ES применяется после этих групп. Поиск сохраняет исходный QuerySet с ограничениями доступа, активности и дистрибьютора. Elasticsearch помогает сортировать совпадения, но не ограничивает их своим индексом или лимитом результатов.

`search_text` — служебное нормализованное поле; модель поддерживает его при `save`, частичных сохранениях, `update`, `bulk_create` и `bulk_update`. Прямой SQL в обход ORM должен поддерживать это поле самостоятельно.

## Применение

```sh
cd autoterra-backend
source .venv/bin/activate
python manage.py migrate
# Если Elasticsearch используется: обновить документы для ранжирования.
python manage.py reindex_products
```

Миграция `0055_product_synonyms` заполняет поиск для всего существующего ассортимента всех дистрибьюторов. Списки синонимов первоначально пусты; нужные названия задаются через Excel или карточку товара.

## Проверка

```sh
DB_ENGINE=sqlite3 SECURE_SSL_REDIRECT=false ALLOWED_HOSTS=testserver,localhost python manage.py test api.test_search api.test_product_import api.test_product_synonym_migration api.test_pagination api.test_client_prices api.test_stock api.test_rank_discounts api.test_distributor --noinput
```

Миграция `0060_product_search_normalization` пересчитывает данные всех товаров (включая неактивные) пакетами по 500. Повторный пересчёт без ES: `python manage.py rebuild_product_search --batch-size 500` (поддерживается `--database`). API `/products/` сохраняет формат ответа.
