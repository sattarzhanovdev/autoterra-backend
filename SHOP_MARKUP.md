# Наценка клиента-магазина

Категория клиента `s` — «Магазин». Выбирается при регистрации и доступна в
существующем управлении клиентами. Миграция `0056_client_shop_markup` добавляет
категорию и `ClientProfile.markup_percent` с начальным значением `0%`.
Существующие категории и клиенты сохраняются.

Перед запуском обновлённого backend применить миграции:

```sh
.venv/bin/python manage.py migrate
```

Активный клиент-магазин получает и сохраняет **свою** наценку:

- `GET /api/me/markup/`
- `PATCH /api/me/markup/` с JSON `{"markupPercent": "30.00"}`

Ответ: `{"clientId": "1", "markupPercent": "30.00"}`. Допускается 0–9999.99%,
до двух десятичных знаков. Посторонние поля (включая `clientId`) отклоняются.
Другие типы клиентов и служебные роли получают 403. В Django admin наценка
доступна только для чтения; управляет ей сам клиент.

`/api/products/` для магазина дополнительно передаёт `markupPercent` и
`markupClientId`. `price` сохраняет значение закупочной цены из существующего
`price_details`: персональная цена → персональная скидка → скидка ранга →
базовая цена. Flutter рассчитывает информационную цену продажи в единственном
`shopSalePrice` с округлением до копеек (half-up). Формула:
`закупочная цена × (1 + наценка / 100)`.

Настройка находится в профиле: «Моя наценка, %». В каталоге и карточке по нажатию
на название показываются закупочная цена, наценка и цена продажи. Успешное
сохранение обновляет все открытые карточки этого клиента через общий notifier;
при выходе из аккаунта его значения очищаются.

Расчёт наценки используется только для отображения. Корзина, заказы, платежи,
бонусы, YooKassa и расчёты дистрибьютора используют прежнюю закупочную цену.
