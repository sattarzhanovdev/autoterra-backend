Изменения бонусов и Android-версий (27.10.2026)

Бонусный баланс по-прежнему равен сумме BonusTransaction. Сгорание и реферальные ставки не изменены. Накопленный оборот каждого приглашённого рассчитывается через Decimal.

POST /api/orders/quote/ принимает items и необязательный bonusAmount (строка с двумя знаками после запятой). Ответ дополнен bonus: balance, maxAllowed, requested, applied, payableTotal — денежные строки. Лимит равен min(баланс, итог после всех обычных скидок × 0.10), округлённому вниз до копейки. Завышенная положительная сумма ограничивается лимитом; отрицательные, нечисловые и некорректные по точности суммы отклоняются. Quote не создаёт операций.

POST /api/orders/create/ и замена заказа сохраняют bonus_requested как выбранную сумму, без списания. При оплате используется существующая транзакционная схема: блокировка заказа, блокировка ClientProfile, актуальный баланс, актуальный серверный итог заказа, лимит 10%, операция order. Поле bonusAmount в запросе оплаты или прежнее useBonus могут переопределить выбор. Если их нет, применяется сохранённый выбор. Повторный запрос переиспользует платёж. Отмена платежа возвращает бонусы операцией refund; повторный возврат не создаёт дубликат. Цены OrderItem бонусами не меняются.

В Django Admin → «Операции по бонусам» → «Списать бонусы» доступна отдельная форма. «Показать баланс» ничего не списывает. Подтверждение требует положительную сумму, непустую причину и разрешение add_bonustransaction. Списание выполняется с блокировкой ClientProfile и записывается в AuditLog. Существующие операции нельзя редактировать или удалять.

GET /api/app-version/?store=google_play&build=22 — публичная проверка Android-версии. Допустимы google_play и rustore. Конфигурации независимы; отсутствующая конфигурация означает отсутствие опубликованного обновления. Поля: latestVersionName, latestBuildNumber, minimumSupportedBuildNumber, updateAvailable, forceUpdate, storeUrl, message. Minimum не может превышать latest. Ссылка должна принадлежать соответствующему магазину и использовать HTTPS.

Конфигурация ведётся через Django Admin → «Версия Android (после публикации в магазине)». Создавать/повышать latest следует только после фактической доступности релиза в конкретном магазине. Нельзя включать minimum для ещё не доступного релиза. Для обычного релиза minimum оставляют на поддерживаемой старой версии. Flutter определяет магазин через Android installer API; если источник неизвестен, предлагает ссылки доступных каналов. Проверка выполняется один раз при запуске и не чаще одного раза в пять минут при возврате из background. Необязательное окно не повторяется для одной версии в одной сессии. Обязательная блокировка находится над маршрутизатором и не снимается переходом на другой экран.

Миграции:

- 0065_order_bonus_requested_androidrelease — сохранённый выбор бонусов, конфигурация магазинов и ограничение minimum ≤ latest.
- 0066_archive_existing_training — однократно архивирует все опубликованные на момент миграции учебные материалы. Записи не удаляются. Новые реальные материалы после миграции публикуются обычным способом. Откат миграции намеренно не публикует архивные материалы автоматически.
