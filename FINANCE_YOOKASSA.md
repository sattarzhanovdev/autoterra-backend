# Внутренний финансовый учет ЮKassa

Отдельный модуль поверх существующих `Order`, `Payment`, `Distributor`.
Создание платежей, webhook, фоновые проверки, наличные, бонусы, скидки и
состояния заказов не изменяются. Импорт **не подтверждает оплату и не делает возврат**.
Данные реестра хранятся в новых таблицах; миграция не переписывает старые записи.

## Доступ и экран

Админ: кнопка «УЧЕТ ЮKASSA» на дашборде, все дистрибьюторы или выбранный.
Дистрибьютор: та же кнопка на главной, только собственные заказы.
Маршрут Flutter: `/finance/yookassa`; клиентам, менеджерам, курьерам и экспертам
доступ запрещен и в маршрутизаторе/экране, и на сервере. Подмена фильтра чужого
дистрибьютора возвращает 403 на всех endpoint-ах.
Дистрибьютор загружает свой реестр; строки, уже связанные с чужими заказами,
пропускаются без раскрытия их деталей. Неопознанная строка относится к загрузившему
дистрибьютору. Неопознанные строки общего админского импорта видны только в общем
отчете админа, пока их платеж не будет найден при повторном импорте.

## Суммы и период

* Только успешные `Payment(provider='yookassa', currency='RUB')`.
* Продажи — сумма `Payment.amount`: фактически оплачено после скидок/бонусов.
  Полностью бонусные, полностью покрытые скидкой и наличные платежи исключены.
* Число заказов — уникальные `order_id`, а не число попыток оплаты.
* Дата продажи — `Payment.paid_at`, для старых платежей без нее — `created_at`.
* Возвраты — отдельные операции по дате возврата, в том числе за старые продажи.
* Комиссия — из реестра, включая указанный НДС и комиссию за чеки; без фиксированного
  процента или предположения о ставке. Если есть только сумма за вычетом комиссии,
  удержание определяется как разница с оплатой.
* Итог = продажи − комиссия − возвраты. При неполной сверке окончательный итог
  неизвестен (`null`); отдельно показана подтвержденная часть. Неизвестная комиссия
  не подменяется нулем. Возвраты с расхождениями исключены из подтвержденных сумм.
* Фильтры периода включают обе календарные даты в часовой зоне Django
  (`Asia/Bishkek`). Даты без часовой зоны в реестре считаются московскими,
  согласно формату времени реестров ЮKassa; ISO даты могут содержать явный offset.

Статусы: `matched`, `not_in_registry`, `payment_not_found`, `amount_mismatch`,
`order_mismatch`, `currency_mismatch`, `payment_not_succeeded`, `fee_unknown`,
`net_mismatch`, `refund_exceeds_payment`. Сверка проверяет сумму против `Payment`,
а не текущей стоимости позиций заказа. Общая сумма всех частичных возвратов
сравнивается с исходной оплатой. Ошибочные суммы не входят в подтвержденный итог.

## Импорт

Поддерживаются русские заголовки стандартных/настраиваемых реестров ЮKassa,
CSV UTF-8/BOM или Windows-1251, разделители `;`, `,`, табуляция; XLSX со всеми листами
(в том числе отдельными «Платежи» и «Возвраты»). Текстовые заголовки договора,
строки периода и итоговые строки официального CSV пропускаются. Денежные значения
принимаются с точкой или запятой, строго до двух знаков после разделителя.

Поля платежа: «Идентификатор платежа», «Сумма платежа», «Время платежа»,
«Сумма комиссии без НДС» / «Сумма комиссии», «НДС с комиссии»,
«Сумма за вычетом комиссии и НДС» / «Сумма за вычетом комиссии».
Поля возврата: «Идентификатор возврата», «Идентификатор платежа»,
«Сумма возврата», «Время возврата», «Валюта возврата».

Также принимается нормализованный формат:

```csv
provider_payment_id;order_id;amount;fee;net;date;currency
2abc-payment;123;1000.00;36.60;963.40;2026-10-05T12:00:00+03:00;RUB
```

```csv
refund_id;provider_payment_id;refund_amount;date;currency
2abc-refund;2abc-payment;200.00;2026-10-07T12:00:00+03:00;RUB
```

Если ID платежа отсутствует, допускается `order_id`, только когда у заказа ровно
один успешный платеж ЮKassa. Непустой неизвестный ID не заменяется совпадением по
заказу. Если оба ID указаны, дополнительно проверяется связь с заказом.
Возврат требует собственного уникального ID; частичные возвраты не объединяются
в один. Платежи и возвраты должны быть отдельными таблицами/листами.

Повторные и перекрывающиеся импорты с теми же операциями не удваивают суммы.
Конфликтующие версии одной операции отклоняют весь импорт с 400; старые данные
не перезаписываются. После исправления/появления отсутствующего локального
платежа повторный импорт привязывает прежнюю неопознанную строку.
Ошибки структуры/чисел/дат отклоняют весь файл атомарно. Максимум 10 МБ,
20 000 строк и 50 МБ распакованного XLSX. Валюты кроме RUB отклоняются.
Аудит импорта: пользователь, область дистрибьютора, имя и SHA-256 файла,
время, число новых и повторных операций. Исходный файл не сохраняется.

Источник формата: https://yookassa.ru/docs/support/merchant/payments/reports/reports-new

## API и выгрузка

Требуется текущий `Authorization: Bearer TOKEN`.

* `GET /api/finance/yookassa/?date_from=2026-10-01&date_to=2026-10-31&distributor_id=1&page=1`
  — итог, операции (по 100), первые 100 расхождений, доступные фильтры админа.
  Итог всегда по всему периоду, независимо от страницы. По умолчанию текущий месяц.
* `POST /api/finance/yookassa/import/` — multipart `file`, необязательный
  `distributor_id` для области импорта админа. Возвращает `importId`, `imported`,
  `duplicates`, `skipped`. Отчет обновляется отдельно с выбранными датами.
* `GET /api/finance/yookassa/export/` — те же фильтры, XLSX со всеми операциями и
  расхождениями за период, без ограничения первой страницей.

В Excel три листа: «Итоги», «Операции», «Расхождения». Денежные ячейки числовые,
есть формат денежных сумм, фильтры и закрепленная строка заголовков.
Пользовательские строки выгружаются как текст, без исполнения формул Excel.
Flutter сохраняет файл через существующий `FileDownloadService` и открывает
системное меню «Поделиться». Ограничение этого сервиса: скачивание в веб-версии
не поддерживается; мобильная/десктопная выгрузка доступна.

## Установка и проверки

На сервере из каталога backend:

```sh
.venv/bin/python manage.py migrate
.venv/bin/python manage.py check
```

Новых зависимостей не требуется: используется уже установленный `openpyxl`.
Перезапустить backend и собрать обновленный Flutter-клиент.
Миграция `0054_yookassa_finance` создает только таблицы учета.

```sh
DEBUG=True DB_ENGINE=sqlite3 .venv/bin/python manage.py test api.test_finance api.test_payments api.test_cash_payments api.test_client_discount api.test_client_prices --noinput
```

Из Flutter-проекта:

```sh
flutter test test/yookassa_finance_test.dart test/cash_payments_test.dart test/payment_start_test.dart test/client_discount_test.dart
flutter analyze lib/screens/finance/yookassa_finance_screen.dart lib/services/api_client.dart lib/app.dart
```
